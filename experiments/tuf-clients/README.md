# Native TUF interoperability probes

These are evaluation programs, not supported installer entry points. They compare
`go-tuf/v2` **2.5.0** and Rust `tough` **0.24.0** against repositories produced by
the existing Python publication code. The libraries are unmodified. Go checksums
and the Cargo lockfile pin the dependency resolutions.

The probes use identical directory-backed transports for a synthetic
`https://fixture.invalid/` namespace. No requests are made to that hostname.
`live` reads the supplied local repository directory; `cache` reads saved
responses with the origin unavailable. This isolates metadata verification from
HTTP implementation differences. HTTPS, redirects, proxies, production download
limits, crash recovery, process locks and GUI/distribution behavior are not
covered by these programs.

## Build and run

Install this repository's Python development dependencies, Go 1.27.4, and Rust
1.100.0. Python is used to generate fixtures and drive native processes; the
compiled probes do not invoke Python. Rust's cryptography dependency also needs
a native C/C++ build environment. From the repository root:

```sh
mkdir -p build/native-tuf
cd experiments/tuf-clients/go
CGO_ENABLED=0 go build -mod=readonly -buildvcs=false -trimpath -o ../../../build/native-tuf/go-probe .
cd ../../..
cargo build --release --locked --manifest-path experiments/tuf-clients/rust/Cargo.toml --target-dir build/native-tuf/rust
python tools/check_native_tuf.py \
  --go build/native-tuf/go-probe \
  --rust build/native-tuf/rust/release/tough-probe \
  --work build/native-tuf/run-1 \
  --report build/native-tuf/report.json
```

Use a new `--work` directory for each run. On Windows, set `CGO_ENABLED=0` in
the environment and use `.exe` output paths. The checked-in result is Linux x64
only; Windows/macOS builds and execution have not been demonstrated by this
evaluation.

An optional `--registry-source /absolute/path/registry-source.json` compares the
authority and all publisher catalogs in an **existing local repository** against
the Python client. It does not modify that repository. It must still have valid
online authorization; the option does not bypass expiry. The saved result used
the real-dashboard Linux fixture generated by `tools/check_dashboard_releases.py`
(registry plus Elastic and AdvantageScope), adding six checks across the clients.
The self-contained suite needs neither Qt nor the dashboard payload downloads.

## Scope and intentional adapter behavior

- The raw-response cache is untrusted. Every root-chain replay begins with the
  original supplied bootstrap and passes through the selected TUF library.
  Root filenames only size the replay limit; they never confer trust. Missing
  cached roots do not count as proof that the online root is current.
- Each bounded invocation fetches at most 256 additional roots. The harness
  computes a library limit large enough to replay the saved prefix plus that
  batch. A budget interruption returns an error without a catalog; a later
  invocation replays the whole prefix and continues. Successful completion
  requires reaching the end of the root chain before fetching current metadata.
- The libraries' own metadata stores retain rollback information. Cache tests
  corrupt all available copies of selected metadata; retaining a valid copy is
  legitimate and must not be mistaken for accepting tampered bytes.
- For `tough` 0.24.0, a transport error returned directly by `fetch` during root
  loading is treated as the end of the root chain. The adapter delivers
  non-missing-file errors through `TransportStream`, which preserves failure
  propagation. The `raw` evaluation mode records the unadapted behavior. This
  is version-sensitive integration code and must remain covered by tests.
- Explicit cache replay still uses normal current-clock expiry checks. There is
  no use of `UnsafeLocalMode`, `ExpirationEnforcement::Unsafe`, a forged clock,
  or a replacement bootstrap root to make the native clients accept online data.
- The `archive` path is separate from TUF refresh. Both probes verify the existing
  Ed25519 registry/bundle envelopes, Python-compatible canonical JSON, the pinned
  archival authority, registry hash binding, publisher provenance, and schema-3
  indefinite authorization. It performs no transport/cache operation and does
  not require online metadata to remain unexpired. Python supplies an independent
  behavioral oracle. The probes intentionally cover **authorization only**:
  they do not implement payload verification/extraction, the full registry
  validator, bounded legacy archival schemas, or the complete bundle loader.

The archive encoders cover the existing integer-based contract and reject
floating-point values. Go accepts arbitrary-size integers; Rust's JSON value
representation limits the supported integer range. The cross-language vectors
include Unicode keys, non-BMP characters, control characters, booleans/null,
and an integer larger than 2^53. A production port must specify/enforce numeric
bounds consistently rather than infer universal serializer equivalence here.

Private keys generated for fixtures stay under the ignored `build` workspace;
do not upload that workspace as a CI artifact. Reports contain outcomes and
public identities/digests only. Binary sizes in the report describe these
different probe builds, not a production-manager size/performance comparison.
