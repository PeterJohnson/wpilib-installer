# Focused C# manager and Native AOT experiment

This follow-up evaluates **Avalonia + C# Native AOT + Tuf 1.1.1 + private Qt**. It does not replace the selected Rust client. The source is under [`experiments/csharp-manager`](../experiments/csharp-manager/README.md); the experiment uses the existing publisher and trust formats without changing production repositories or publication workflows.

## Implemented policy adapters

The unmodified `Tuf` library still verifies signatures, successive root transitions, both root thresholds, expiry, metadata relationships and target hashes. The adapter always supplies the original bootstrap as the root cache entry, then replays persisted root responses through the library. A valid self-signed replacement in the library-local cache cannot become a new anchor. Each root is saved only after the library accepts it; missing or altered evidence fails closed.

A 256-new-root budget returns `root-update-pending` before any timestamp or catalog is consumed, even when intermediate roots have not expired. Subsequent invocations reauthenticate the saved prefix and continue. Rollback checkpoints survive failures; atomic flushed writes and a repository-state lock are mandatory. The checkpoint itself remains trusted local state, not protection against a local administrator deleting/replacing the whole installation. Cached-root replay remains proportional to the saved history; the budget bounds new network work rather than the total cryptographic replay work.

Online catalog transport supports bounded HTTP(S), rejects redirects, and uses explicit verified-cache mode. An HTTP/server error never automatically selects cached data. Registry refresh checks scope, validity and monotonic registry revision, then obtains independently authenticated catalogs from the registry's dynamic publisher list. The experiment does not yet select release combinations, validate every publisher release envelope, or stream large package payloads.

Offline schema-3 authorization is a separate C# implementation of the pinned archival authority policy. Its Python-compatible canonical encoding includes ASCII escapes, supplementary Unicode key ordering, and full 64-bit integers. Authorization has no clock dependency and never opens an online cache. The checks include old media with expired online authorization, archival-key rotation, and online catch-up through 1,030 roots. Full bundle payload validation remains in the existing Rust client.

## Native distribution

The application contains a basic Avalonia catalog-check GUI and the same policy CLI. The build embeds the pinned Qt worker and, on Linux, its private runtime. Avalonia's native rendering libraries are carried privately too. A small AOT launcher extracts the native application and libraries into a fresh private temporary directory, forwards arguments/stdout/exit status, waits for completion, and removes the temporary directory. Windows cleanup retries delayed file releases and reports a leftover temporary directory rather than replacing a completed operation’s exit status; directories left by a crash or exhausted retries are never reused as trusted executable caches. Qt receives its private library/font environment only in its child process. There is one public executable on Windows/Linux and one application bundle on macOS; Python and an installed .NET runtime are not used by client operations.

This packaging is intentionally easy to measure and test, not necessarily the smallest or fastest final design. It adds a second private native executable and per-launch extraction. In-process loading of embedded rendering libraries may reduce launcher overhead. Persistent extraction requires an authenticated, crash-safe cache and update/signing design.

The GUI currently checks catalogs. It does not implement the Rust client's install/update/uninstall transaction, profile selection, package resolver, maintained installed application, cancellation/progress, or self-update. Consequently the measured application is a concrete packaging comparison, **not feature parity**. Additional manager code will affect its eventual size. Hosted-runner startup also does not establish pristine-machine or signing/notarization acceptance.

## Acceptance and sizes

**All four targets passed:** 43 policy checks each on Linux/macOS, 44 on Windows (the extra check repeats pending exit handling in 12 separate processes), plus native GUI startup and private Qt worker startup on every target. That is 173 policy checks. The [evidence report](evidence/csharp-manager-2026-11-28.json) preserves exact executable hashes, dependency inventories, artifacts, jobs, and assertions.

Linux x64 and both macOS architectures passed in [run 46096536506](https://github.com/PeterJohnson/wpilib-installer/actions/runs/46096536506) at `43988d7`; its Windows audit initially rejected the Windows GDI FontSub.dll as unknown. The corrected Windows build and native suite passed in [run 46097305756](https://github.com/PeterJohnson/wpilib-installer/actions/runs/46097305756) at `8d171ac`. Changes after `43988d7` concern the Windows import allowlist/cleanup and test diagnostics, not the TUF or archival verifier. The earlier run's aggregate failure is not represented as an all-green workflow.

The tests execute actual Native AOT binaries on Ubuntu 22.04 x64, Windows Server 2022 x64, and macOS 15 Intel/ARM64. They target .NET 10 with runtime/ILCompiler 10.0.15; Windows, Linux and macOS ARM64 selected SDK 11.0.100; macOS Intel selected SDK 10.0.404. The runtime/ILCompiler and application package versions were the same. Neither an installed .NET runtime nor Python is invoked by the application. Python is the fixture generator/oracle. The Windows PE import audit found only OS/private dependencies, including [FontSub.dll, a documented Windows GDI library](https://learn.microsoft.com/en-us/windows/win32/api/fontsub/nf-fontsub-createfontpackage). Linux Skia uses the desktop's fontconfig stack; the dependency inventory is not proof of clean-machine compatibility.

The application checks cover registry/publisher catalogs generated by the real tooling, including the core, Elastic, AdvantageScope and RobotPy fixture publishers. They exercise cached-root replacement, expired intermediate roots, both rotation thresholds, resumable 1,030-root histories, cache tampering/expiry, registry and TUF rollback, independent archival-key rotation, dynamic publisher additions, HTTP limits/redirect refusal and fatal cache-write failures.

C# downloads are roughly 26–28% larger in this experiment. The main additional footprint is the Avalonia/AOT application and native rendering stack: Skia and HarfBuzz total 13.3 MiB uncompressed on Linux; Windows includes 18.0 MiB of rendering DLLs including ANGLE; macOS carries 18.8 MiB of native GUI/font/rendering libraries. The Mac libraries include both CPU slices, so architecture thinning is an unmeasured size-reduction opportunity. Qt remains shared overhead: its compressed worker is about 17.7 MiB on Windows, 33.2 MiB on Mac and 20.1 MiB on Linux, with a further 6.6 MiB Linux private runtime. The launcher adds extraction cost and native code of its own; no claim is made that this is the minimum achievable C# size.

The first Linux measurement was discarded for comparison because its runtime-notices collection included unrelated hosted-runner packages. The final build uses the same minimal runtime container as Rust. Windows required explicit child stdout/stderr forwarding. A later Windows process emitted correct pending JSON but exited abnormally; the original harness did not capture its stderr, so delayed temporary-image cleanup was a hypothesis rather than a proven cause. Cleanup now has bounded retries and cannot replace the operation result, stderr is retained on abnormal exits, and the final suite plus repeated pending processes passed. This does not replace longer-running reliability/crash tests.
 The Rust baseline is the successful [installer client run 46082370013](https://github.com/PeterJohnson/wpilib-installer/actions/runs/46082370013), commit `e40b48f7f369dceb6e46add87102590ca1f3eeb5`. That client implementation is unchanged by the experiment.

Both distributions contain IFW 4.11.0 with the same worker configuration, public fixture bootstrap and Linux private-worker dependency policy. Qt engines are freshly generated, so timestamps/bootstrap bytes can differ. Both measurements exclude debug symbols, use unsigned development binaries and ZIP downloads, and exclude separately downloaded package bundles. The C# public executable already contains a compressed private application, whereas Rust embeds its code directly; compare ZIP downloads as well as raw executable sizes, not just the latter. The Linux Rust baseline was compiled in Ubuntu 22.04; the C# Linux job also builds on Ubuntu 22.04.

## Decision limits

**Recommendation: pure C# is a viable candidate; retaining Rust is no longer necessary solely for TUF or AOT support.** Prefer a C# migration if sharing the UI and manager language is worth the measured download overhead and the work to port/review the existing lifecycle code. Otherwise, Avalonia over the tested Rust core remains a sensible reuse option. Do not switch the production client solely on this limited experiment.

The C# experiment addresses the TUF-library availability and AOT feasibility questions. It does not eliminate the cost of porting and reviewing application policy. Before choosing it for the production client, retain the same acceptance gates as Rust and finish release-envelope validation, package resolution, payload verification and installed maintenance. Review checkpoint handling across signing-role resets, root-history replay cost, malformed metadata/URL cases, concurrent/crash/power-loss behavior, filesystem links and cache permissions. Run an independent security review of both dependency and adapter.

Windows/macOS signing, notarization and quarantine behavior remain open. Avalonia/Skia and .NET native system-library requirements require clean-machine coverage; the absence of an installed .NET runtime requirement alone does not prove every OS dependency is bundled. The extra GUI framework/Skia payload and the Qt worker should be compared against the benefit of maintaining a C# UI and manager together. Retaining Rust behind Avalonia remains available if its existing policy/lifecycle implementation is preferable to a full port.
